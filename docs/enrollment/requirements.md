# 招生报名家长端 H5 一期需求文档

> 文档状态：根据 UI 反馈修订，待复核（2026-08-25）  
> 产品范围：家长端招生报名 H5 及其必要服务端能力  
> 不包含：教师审核页面、内容配置后台、短信通知、独立消息中心

## 1. 建设目标

面向准备进入幼儿园、小学和初中的学生家庭，提供学校选择、信息填报、部门数据辅助查询、材料上传、报名提交、审核结果查看和录取结果查询能力。

一期以家长端为核心，重点降低家长重复填写成本，同时保证：

1. 系统只负责信息采集、数据呈现、完整性及格式校验，不自动判断家庭是否符合学校招生条件。
2. 所有资格判断均由学校老师完成。
3. 部门数据查询失败不能阻断报名，家长始终可以手工补充。
4. 已查询数据允许修改，但必须保留原值、申报值和修改痕迹。
5. 招生政策与学校差异通过配置驱动表单表达，避免为每所学校重复开发页面。

## 2. 用户与使用边界

### 2.1 主要用户

- 家长或其他实际报名操作人
- 通过现有 H5 应用壳的统一实名身份进入招生报名模块

### 2.2 身份与数据归属

- 招生报名不建设独立登录体系。
- 报名创建时绑定统一平台的实名用户标识。
- 后续草稿、报名记录、材料和结果仅允许报名创建人访问。
- 表单中的父亲、母亲和其他监护人属于申报资料，不参与系统访问授权。
- 公开二维码查询页不依赖登录态，只能返回严格受限的脱敏结果。

## 3. 一期范围

### 3.1 家长端页面

1. 首页
2. 报名时间
3. 招生政策列表与详情
4. 常见问答
5. 查学区及查询结果
6. 操作指南
7. 报名入口、类别选择和学校选择
8. 学校政策阅读与确认
9. 数据预处理（学生查询条件、授权及部门数据查询）
10. 报名信息时间轴总览
11. 各信息簇独立编辑页面
12. 独立的信息预览与真实性确认页面
13. 提交成功
14. 我的报名列表与报名详情
15. 退回修改
16. 初审公示二维码查询
17. 最终录取二维码查询
18. 通用空状态、异常提示和接口失败降级页面

### 3.2 必要服务端能力

- 招生门户内容读取
- 招生目录及政策读取
- 配置驱动表单
- 草稿、提交、版本和状态流转
- 部门数据核验适配
- MinIO 图片材料管理
- 审核接口及操作记录，为后续教师端预留
- 初审、录取公开查询及统一发布控制

### 3.3 明确不做

- 教师审核前端
- 内容及招生配置管理前端
- 短信通知
- 独立消息中心或首页消息入口
- 在线客服或在线提问
- 视频操作教程
- 地图选点
- 系统自动判定报名资格
- Redis

## 4. 首页信息架构

首页采用块状服务门户，不设置底部 TabBar。

### 4.1 首页区域

1. 顶部 Banner
2. 三个报名入口
3. 招生服务入口
4. 我的报名
5. 咨询电话与服务说明

### 4.2 Banner

- 支持后台数据配置，最多 3 张轮播。
- 可配置图片、排序、有效期及跳转内容。
- 只有一张时静态展示。

### 4.3 三个报名入口

- 幼儿园入学报名
- 幼升小报名
- 小升初报名

### 4.4 招生服务入口

- 报名时间
- 招生政策
- 常见问答
- 查学区
- 操作指南

### 4.5 我的报名

- 展示最近一条报名摘要及其最新状态。
- 提供“查看全部”入口。
- 状态或审核内容发生变化时显示“有更新”，查看后消除。
- 无报名记录时展示报名引导。

## 5. 招生公共内容

### 5.1 报名时间

- 自动使用当前开放的招生年度，家长不能手动选择年份。
- 按招生年度、学段、城区／非城区／民办分类。
- 仅展示开始时间和截止时间。
- 不展示“未开始／报名中／已结束”等当前状态。

### 5.2 招生政策

- 先选择学段和城区／非城区／民办。
- 展示区县统一政策及各学校招生政策。
- 支持按学校名称搜索。
- 政策详情采用图文内容。
- 招生政策、表单规则和材料清单在开放报名前确定，报名期间不考虑变更。

### 5.3 常见问答

- 采用一问一答形式。
- 分类包括：报名准备、学校选择、信息填写、材料上传、审核与修改、录取结果。
- 支持关键词搜索。
- 不提供家长在线提问。

### 5.4 查学区

- 支持输入小区、道路或详细地址。
- 返回可能对应的学校及招生范围说明。
- 明确提示“查询结果仅供参考，请以当年招生政策和学校审核为准”。
- 不提供地图选点。
- 不自动带入或限制报名学校。

### 5.5 操作指南

- 采用图文步骤说明。
- 覆盖选择报名入口、选择学校、填写资料、上传材料、提交报名、查看审核结果和处理退回修改。
- 可按三个学段分别配置内容。

### 5.6 一期维护方式

一期仅建设数据结构、读取接口和初始化数据，不建设内容配置后台。内容暂通过初始化数据或接口导入维护。

## 6. 报名主流程

1. 进入三个学段入口之一。
2. 选择城区、非城区或民办。
3. 选择目标学校。
4. 阅读并勾选确认学校政策。
5. 进入数据预处理页，选择关联学生，或输入学生姓名和证件号码作为查询条件。
6. 阅读数据查询说明并完成一次授权，集中查询本次报名需要的部门共享数据。
7. 进入报名信息时间轴总览，查询结果自动带入各信息簇；失败或缺失内容允许手工补充。
8. 从时间轴节点分别进入独立编辑页面填写报名资料。
9. 跳转至独立预览页面，查看全部信息并勾选真实性声明。
10. 正式提交，进入审核中。
11. 在“我的报名”查看退回、初审及最终录取结果。

## 7. 学校选择规则

- 学校列表仅按招生年度、学段和城区／非城区／民办筛选。
- 不依据户籍、房产或现住址隐藏学校。
- 家长自行阅读招生范围并选择学校，最终由老师审核。
- 学校列表展示学校名称、类别、地址、招生范围摘要、报名日期和政策入口。
- 不展示剩余名额，也不展示“未开始／报名中／已结束”等当前状态。
- 支持按学校名称搜索。
- 同一学生、同一招生年度、同一学段，同一时间只能存在一条有效报名。
- 待提交阶段允许更换学校。
- 正式提交后不能自行撤回。
- 初审不通过后，原报名保留为历史记录，家长可重新选择学校并创建新的报名。

## 8. 政策与表单配置

采用“区县公共规则＋学校差异规则”：

- 区县公共规则配置招生年度、学段和城区／非城区／民办的共同要求。
- 学校差异规则配置招生范围、材料要求、信息核验项及特殊说明。
- 学校规则用于补充公共规则。
- 家长提交时固化当时适用的政策版本、授权版本、声明版本和材料清单。
- 表单采用配置驱动，但身份权限、状态流转、提交防重等关键规则由代码控制。
- 一期使用预置配置或接口导入，不建设可视化规则编辑器。

## 9. 报名填写交互

### 9.1 数据预处理

数据预处理位于学校选择及政策确认之后、时间轴之前。

- 从关联学生中选择一人，或输入学生姓名和证件号码作为查询条件。
- 这里只采集部门查询必需的最少信息，不编辑完整学生资料。
- 完成一次数据查询授权后，集中查询户籍、不动产、社保、营业执照及父辈无房证明等本次需要的数据。
- 查询结果在进入时间轴时自动带入对应信息簇。
- 查询失败或只返回部分数据不能阻断报名，缺失内容在独立编辑页手工补充。

### 9.2 时间轴范围

时间轴是“报名信息总览”，不直接展开和编辑表单，也不用于展示审核或录取流程。

时间轴信息簇：

1. 学生信息
2. 家庭及户籍信息
3. 房产及居住信息
4. 材料上传

交互要求：

- 每个节点展示完成情况、关键数据摘要、数据来源和待补充提示。
- 节点采用与信息预览一致的移动端分组样式，支持展开或折叠已填写数据。
- 节点右侧折叠箭头只负责展开或收起数据；独立的“修改”操作进入该信息簇的编辑页面。
- 时间轴可展示已填写数据，但不直接出现可编辑输入框。
- 社保、营业执照、父辈无房证明等条件性内容并入“材料上传”，按政策和家庭情况动态展示。
- 时间轴底部提供“预览并提交”，跳转至独立预览页面；预览不作为时间轴节点。
- 部门查询状态展示“已自动补充／用户已修改／查询失败已手填”。

### 9.3 独立编辑页与草稿

- 每个时间轴信息簇都有独立编辑页面。
- 编辑页填写过程自动保存。
- 保存后返回时间轴并刷新该节点摘要。
- 返回或退出后可继续填写。
- 显示最近保存时间。
- 网络异常时保护当前页输入并提示重试。

### 9.4 数据授权

- 采用一次说明、一次授权、按需查询。
- 说明数据来源、查询内容和使用目的。
- 记录授权人、授权时间和授权文本版本。
- 仅查询当前学校政策和家庭情况所需数据。
- 授权不代表系统自动判断报名资格。

### 9.5 预览与提交

- 预览与提交使用独立的完整长页面，不嵌入时间轴。
- 页面高度随数据自然增长，不为适应单屏而压缩数据项、字号或间距。
- 各信息簇分区展示，长字段自然换行，部门原值与申报值上下对照。
- 材料按名称和缩略图分组展示。
- 突出标识人工填写和修改过的部门数据。
- 家长勾选真实性声明，不采集手写签名。
- 保存声明版本、勾选时间、实名身份、报名版本、政策版本和授权版本。
- 正式提交生成唯一提交凭证并校验报名版本，防止网络重试产生重复报名。
- 提交瞬间保存完整数据快照。

## 10. 报名信息

### 10.1 学生信息

公共字段：

- 姓名
- 证件类型
- 证件号码
- 学生证件照
- 户籍所在地
- 当前居住地址

不采集：性别、出生日期、民族。

学段差异：

- 幼儿园入学报名：不采集原就读学校。
- 幼升小报名：原幼儿园选填。
- 小升初报名：采集原小学和学籍号。

学生证件照要求：

- 近期正面免冠照。
- 支持拍照和相册选择。
- 支持裁切为 3:4。
- 建议纯色背景，不严格限定背景颜色。

### 10.2 家庭成员

成员模型：

- 学生
- 当前监护人
- 父亲
- 母亲
- 可选其他法定监护人

父亲或母亲信息缺失时可选择离异、去世、未知或其他原因。

监护人／父母字段：

- 与学生关系
- 姓名
- 证件类型
- 证件号码
- 联系电话

不采集工作单位和“是否为当前报名操作人”。

### 10.3 户籍信息

只采集户主和监护人两类人员：

- 姓名
- 证件号码
- 联系电话
- 户籍地址
- 与学生关系

不采集落户时间。户口簿图片仅在学校政策要求或部门接口失败时动态出现。

### 10.4 房产信息

本次报名只能选择一套房产作为报名依据，字段包括：

- 不动产权利人
- 权利人证件号码
- 与学生关系
- 不动产权证号
- 房产地址
- 房产用途
- 建筑面积

不采集共有情况。

### 10.5 社保信息

- 核验对象可选择父亲、母亲或其他法定监护人中的一人。
- 展示参保人、证件号码、参保地区、参保状态、首次参保时间和连续缴纳月数。
- 系统只展示数据，不判断是否满足学校要求。

### 10.6 营业执照信息

- 一次报名只能选择一个营业执照作为依据。
- 经营主体可属于父亲、母亲或其他法定监护人。
- 字段包括统一社会信用代码、市场主体名称、经营者或法定代表人、主体类型、注册地址、成立日期、登记状态及与学生关系。
- 查询失败时允许手填并上传营业执照图片。

### 10.7 父辈无房证明

- 仅在使用祖辈房产且目标学校要求时出现。
- 同时核验学生父亲和母亲双方名下无房，并分别展示结果。
- 结果包括姓名、证件号码、核验区域、核验时间和有房／无房／未查到结果。
- 单亲、离异、去世等特殊情况允许填写说明并上传证明材料。
- 接口失败不能阻断报名。

### 10.8 条件性信息原则

- 社保、营业执照主要面向外来人员且无房、无本地户籍的情形。
- 父辈无房证明只在使用祖辈房产且部分学校明确要求时出现。
- 系统依据学校政策及家长已填信息控制字段和材料显隐，但不据此判断资格。

## 11. 部门数据核验

接入范围：

- 不动产信息
- 户籍信息
- 社保信息
- 营业执照信息
- 父辈无房证明

处理规则：

- 所有部门接口通过统一数据核验层接入。
- 一期使用模拟接口，后续替换真实接口不改变报名流程。
- 查询结果允许家长修改。
- 普通字段可直接修改；身份、户籍、房产和社会身份等关键字段修改时必须填写原因，可按政策上传证明。
- 保存数据来源、接口版本、查询时间、结果状态、原始数据快照、最终申报值、修改标记、修改原因和失败原因。
- 部门接口恢复后不得静默覆盖家长已经填写或修改的数据。
- 接口失败立即提供手工填写入口，并按学校政策展示证明材料上传项。

## 12. 图片材料

- 仅支持图片，不支持 PDF 或 Word。
- 支持拍照和相册选择。
- 支持预览、替换、删除和排序。
- 每个材料项最多 10 张。
- 单张原图最大 10 MB。
- 上传前后将单张图片压缩至 2 MB 以内，并纠正图片方向，在保证文字清晰的前提下控制尺寸。
- 文件存储于 MinIO 私有桶，PostgreSQL 只保存文件元数据和业务关联。

## 13. 审核与修改

教师端未来提供三种初审操作：

- 退回修改
- 通过
- 不通过

要求：

- 退回修改必须标记具体字段或材料并填写原因。
- 初审不通过必须填写原因。
- 家长处理退回时，问题项优先定位并高亮，但允许修改其他信息。
- 再次提交生成新的报名版本，保留前后差异。
- 初审通过后状态可立即变化，线下审核时间、地点、材料和注意事项可稍后统一公布。

## 14. 状态模型

报名状态：

- 待提交
- 审核中
- 退回修改
- 初审通过
- 初审不通过
- 已录取

状态流转：

1. 待提交 → 家长提交 → 审核中
2. 审核中 → 老师退回 → 退回修改
3. 退回修改 → 家长再次提交 → 审核中
4. 审核中 → 老师通过 → 初审通过
5. 审核中 → 老师不通过 → 初审不通过
6. 初审不通过 → 家长重新选择学校 → 创建新的待提交报名
7. 初审通过 → 管理端确定录取学校并发布 → 已录取

补充规则：

- 不设置“待线下审核”，初审通过本身代表已进入线下审核范围。
- 不设置“未录取”。暂未确定录取学校的报名继续保持初审通过。
- 需要补录或调整学校时由管理端处理，确定后直接进入已录取。
- 初审公示是否发布、最终录取结果是否发布使用独立发布控制，不增加报名状态。

## 15. 我的报名

- 默认展示当前招生年度报名。
- 支持按年度、学生和学段筛选历史记录。
- 历史记录只读，并保留政策、授权、声明、材料和审核版本。
- 报名详情直接展示当前状态、退回原因、审核意见、线下安排和最终录取结果。
- 不建设独立消息中心。

## 16. 初审与录取公开查询

### 16.1 发布方式

- 初审结果由管理端统一发布，不按学校或类别分批。
- 发布前，登录家长可以在报名记录看到“初审通过”，线下安排未确定时显示“线下审核安排待公布”。
- 统一发布后，初审公开查询才可使用。
- 最终录取结果同样由管理端统一发布后开放。
- 初审公示和最终录取使用两个独立二维码及查询页。

### 16.2 查询验证

- 学生姓名
- 学生证件号码后六位
- 图形验证码

安全控制：

- 对同一设备和网络地址限制查询频率。
- 连续失败后短暂锁定。
- 查询失败统一提示“未查询到匹配结果或信息有误”。
- 不允许通过错误差异判断学生是否存在。

### 16.3 查询结果

- 学生姓名只显示姓氏和末尾一个字。
- 证件号码只显示后四位。
- 不展示监护人、户籍、房产及其他报名资料。
- 初审查询只展示初审结果和线下审核安排。
- 最终查询只展示已发布的录取结果；尚未确定时显示“录取结果待公布”。

## 17. 安全与审计

- 业务接口只信任服务端验证后的统一平台身份。
- 报名数据按创建人隔离。
- 证件号码、联系电话等敏感字段加密保存。
- 页面和接口按使用场景脱敏。
- 运行日志、错误信息和统计数据不得记录完整证件号、手机号、房产证号等敏感信息。
- 查询、修改、提交、审核、发布和材料访问均记录操作日志。
- 公开查询接口与登录后的家长接口完全隔离。
- 所有报名数据、审核记录和上传材料一期默认长期保留。

### 17.1 MinIO 安全要求

- 使用私有存储桶，禁止公开直链。
- 通过受控接口上传和查看。
- 查看时使用短时有效访问地址。
- 服务端校验真实图片格式、文件大小和扩展名。
- 文件名使用随机标识，不包含个人敏感信息。
- 按报名归属校验材料访问权限。
- 删除或替换材料时保留操作记录。

## 18. 技术与模块边界

招生报名作为平台中的独立业务模块，不与其他应用互相依赖。

业务能力拆分：

- 招生门户
- 招生目录
- 报名申请
- 家庭资料
- 数据核验
- 材料中心
- 审核衔接
- 公示查询

前端基于现有 React、Vite、Ant Design Mobile 和应用注册机制；未来教师管理端使用 Ant Design Pro。后端按独立招生领域模块组织，复用平台身份、文件、数据库、日志和错误处理能力。

本地测试环境：

- Docker PostgreSQL
- Docker MinIO
- 前端和后端服务在本机运行
- 不使用 Redis

## 19. UI 方向与首轮交付

视觉方向采用“可信政务服务＋亲和教育场景”：

- 沿用现有平台品牌色。
- 简洁、稳重、清晰易读。
- 使用温和辅助色和适量学生主题插画。
- 不采用只适用于低龄儿童的幼儿化卡通风格。
- 基于 Ant Design Mobile 建立统一品牌样式，不直接照搬组件默认外观。

## 20. 验收原则

1. 家长可以在不依赖部门接口成功的情况下完成并提交报名。
2. 系统不会显示或输出自动资格判定结果。
3. 部门原始数据、家长申报数据及修改记录可追溯。
4. 同一学生、同一年度、同一学段同一时间只能存在一条有效报名。
5. 正式提交、退回再提交和审核操作均具有完整版本记录。
6. 公开查询不能访问完整报名资料，且具备防批量枚举措施。
7. 未经统一发布，公开查询不能提前看到初审或录取结果。
8. 所有图片材料通过 MinIO 私有存储并按报名归属授权访问。
9. 页面不使用底部 TabBar，报名填写使用可查看完整结构的时间轴。
10. 首页包含 Banner、三个报名入口、报名时间、招生政策、问答、查学区、操作指南和我的报名。
