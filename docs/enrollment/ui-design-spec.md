# 招生报名家长端 H5 UI 设计规范

> 文档状态：根据 UI 反馈修订，待复核（2026-08-25）  
> 适用范围：招生报名家长端 H5、初审公开查询页、录取结果公开查询页  
> 设计基线：React + Ant Design Mobile，复用现有 H5 应用壳

## 1. 设计目标

招生报名承载大量家庭敏感信息和重要升学事项，界面需要同时满足可信、清晰、亲和与低操作负担。

设计原则：

1. **可信而不生硬**：保持政务服务的稳定感，通过温和辅助色和教育场景插画降低紧张感。
2. **先任务、后说明**：报名、修改和结果查看是最高优先级，说明内容不抢占主要操作。
3. **完整流程可见**：报名填写使用纵向信息时间轴，让家长随时知道还需要准备什么以及最终提交位置。
4. **不代替老师判断**：颜色、文案和图标只表达信息状态，不表达“符合／不符合招生条件”。
5. **减少重复填写**：自动查询、手工补充和修改标记必须清楚，但不增加家长理解成本。
6. **适合单手操作**：关键操作位于易触达区域，触控目标充足，输入和上传流程尽量短。

## 2. 运行与画布

- 招生报名是现有 H5 应用壳中的独立业务模块，不是内嵌 WebView 页面。
- 家长报名页面继承应用壳的实名身份和页面容器。
- 初审与录取二维码查询页可脱离应用壳，在移动浏览器独立打开。
- 设计基准画布：390 × 844 px。
- 最低支持宽度：320 px；重点验证 360、375、390、414 px。
- 桌面访问时内容区最大宽度沿用平台 760 px，居中显示，不拉伸成桌面后台。
- 顶部、底部操作区考虑浏览器安全区域。

## 3. 视觉方向

### 3.1 气质

- 关键词：可信、清楚、从容、温和、现代。
- 不采用幼儿化卡通风格，因为同时服务幼儿园、小学和初中家庭。
- 不使用大面积高饱和渐变、玻璃拟态或过度悬浮效果。
- 插画只用于 Banner、空状态和结果引导，不进入密集表单区域。

### 3.2 色彩

沿用现有平台蓝色体系，并补充功能色。

| 用途 | 色值 | 使用说明 |
|---|---:|---|
| 品牌主色 | `#2457D6` | 主按钮、当前节点、链接、重点入口 |
| 品牌深色 | `#173FA8` | Banner 深色端、重要标题背景 |
| 品牌浅色 | `#EDF3FF` | 入口图标底、选中态浅背景 |
| 页面背景 | `#F4F6FA` | 全局页面底色 |
| 卡片背景 | `#FFFFFF` | 内容卡片、表单区域 |
| 主文字 | `#172033` | 标题、主要数据 |
| 次文字 | `#697386` | 描述、辅助说明 |
| 弱文字 | `#8A94A6` | 占位、时间、次级标签 |
| 分割线 | `#E4E9F1` | 卡片边界、列表分割 |
| 成功 | `#17845B` | 已完成、已录取、保存成功 |
| 提醒 | `#B86B00` | 待补充、有更新、安排待公布 |
| 错误 | `#C63F3F` | 校验失败、初审不通过 |

使用约束：

- “初审通过”可以使用成功色，但必须配合明确文案，不能暗示最终录取。
- 部门接口“未查到结果”和“查询失败”使用中性或提醒色，不使用资格不通过式红色。
- 学校卡片不使用报名中、已结束等状态色。
- 文本与背景对比度满足常规文字可读性要求，不能仅靠颜色区分状态。

### 3.3 字体与字号

字体沿用系统字体：

```text
-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif
```

| 层级 | 字号 / 行高 | 字重 | 用途 |
|---|---|---|---|
| 页面主标题 | 24 / 32 | 700 | 首页主标题、结果主标题 |
| 页面标题 | 20 / 28 | 700 | 二级页面标题 |
| 区块标题 | 18 / 26 | 600 | 首页区块、表单分区 |
| 卡片标题 | 16 / 24 | 600 | 学校名、入口名、时间轴节点 |
| 正文 | 16 / 24 | 400 | 表单值、政策正文、主要说明 |
| 辅助正文 | 14 / 22 | 400 | 描述、地址、提示 |
| 标签与说明 | 12 / 18 | 500 | 状态标签、更新时间 |

- 输入控件字号固定为 16 px，避免移动浏览器自动缩放。
- 重要政策和真实性声明正文不小于 15 px。
- 长文本使用自然换行，不用缩小字号强行放入一行。

### 3.4 间距与圆角

基础间距：4、8、12、16、20、24、32 px。

- 页面左右留白：16 px。
- 卡片内边距：16 px；紧凑列表可使用 12 px。
- 区块间距：20 或 24 px。
- 普通卡片圆角：14 px。
- Banner 圆角：0（通栏）或 18 px（壳子内留白样式），全应用只选择一种。
- 输入框和选择器圆角：10 px。
- 主按钮圆角：12 px。
- 标签圆角：6 px，不使用胶囊形态堆满页面。

### 3.5 阴影与边框

- 卡片默认采用 `1px #E4E9F1` 边框和极轻阴影。
- 重点卡片阴影建议：`0 6px 20px rgba(26, 44, 82, 0.06)`。
- 表单、政策正文等长内容区域以边框和背景层级为主，不叠加重阴影。

## 4. 页面框架

### 4.1 页面头部

- 首页不使用常规导航栏，顶部直接进入 Banner。
- 二级页面使用简洁标题栏：返回、页面标题；仅在必要时提供右侧文字操作。
- 不放置消息铃铛或独立消息入口。
- 二维码公开查询页使用独立品牌头部，不显示应用壳的个人信息。

### 4.2 页面底部

- 不设置底部 TabBar。
- 普通内容页随页面自然滚动。
- 报名填写和预览提交页允许使用底部固定主操作区，并为安全区域留白。
- 固定操作区只能放一个主操作和最多一个次操作，不遮挡时间轴节点或错误提示。

### 4.3 返回与离开

- 草稿已自动保存时可直接返回，并显示最近保存时间。
- 当前内容保存失败时，离开前提示尚未保存，提供“继续填写”和“仍要离开”。
- 浏览器返回与页面返回行为一致。

## 5. 首页规范

首页从上到下建议顺序：

1. Banner
2. 三个报名入口
3. 我的报名
4. 招生服务
5. 咨询电话与服务说明

### 5.1 Banner

- 建议高度 156–176 px。
- 主标题不超过 14 个汉字，辅助文案不超过两行。
- 插画主体放在右侧，文字保持左对齐。
- 最多 3 张轮播；轮播指示器不遮挡文字。
- 单张时不显示无意义的轮播指示器。

### 5.2 三个报名入口

- 三张纵向卡片或一主两辅布局，不能缩成难以点击的三等分小按钮。
- 每张展示正式名称、简短对象说明和方向图标。
- 不展示资格标签、人数、名额或当前报名状态。
- 点击后进入城区／非城区／民办选择。

### 5.3 我的报名

- 有记录时展示学生脱敏姓名、报名学校、学段、最新状态和最近更新时间。
- 状态发生变化时显示小型“有更新”标识，查看详情后消失。
- 退回修改时直接露出退回原因摘要和“去修改”主操作。
- 初审通过但安排未发布时显示“线下审核安排待公布”。
- 无记录时使用简洁引导，不渲染一张空白报名卡。

### 5.4 招生服务

- 五个块状入口：报名时间、招生政策、常见问答、查学区、操作指南。
- 推荐 2 列网格，其中“招生政策”或“查学区”可作为较宽重点入口。
- 使用线性图标，不使用 Emoji。

## 6. 报名入口与学校选择

### 6.1 类别选择

- 页面明确显示当前学段。
- 城区、非城区、民办采用三张大卡片纵向排列。
- 每张卡片只解释类别含义，不根据家庭资料推荐或判断。
- 已选择项使用主色边框、浅色底和勾选图标共同表达。

### 6.2 学校列表

- 顶部固定搜索框，支持按学校名称搜索。
- 可显示当前筛选：招生年度、学段、类别。
- 学校卡片展示学校名称、类别、地址、招生范围摘要、报名开始及截止时间、政策入口。
- 地址和招生范围过长时最多展示两行，并提供详情查看。
- 不展示当前状态和剩余名额。
- 整张卡片可选，政策入口作为独立文字链接，避免点击冲突。

### 6.3 政策阅读

- 顶部展示学校名称、招生年度、学段和类别。
- 正文区保持 16 px 字号及舒适行距。
- 页面底部展示“我已阅读并理解”勾选项和继续按钮。
- 未滚动到底不强制阻塞勾选，但必须记录明确勾选动作。
- 提交后可从报名详情查看当时的政策版本。

## 7. 数据预处理

数据预处理位于学校选择及政策确认之后、时间轴之前，用于一次性准备报名共享数据。

### 7.1 查询对象

- 已关联学生采用单选卡片，展示脱敏姓名、证件类型及证件号后四位。
- 多个孩子时必须明确当前查询对象。
- 未查询到关联学生时，允许输入学生姓名和证件号码作为查询条件。
- 这里只采集查询所需的最少信息，不编辑完整学生资料；完整学生信息在时间轴对应编辑页补充。

### 7.2 授权与查询

- 同一页面说明查询来源、内容和用途，并完成一次授权。
- 重点说明“仅用于减少填写，不作为系统自动判定资格的依据”。
- 不逐个接口弹出授权弹窗。
- 主操作使用“授权并查询共享数据”。
- 查询过程中分别展示户籍、不动产、社保、营业执照及父辈无房证明的进度。
- 查询完成后展示成功、未查询到和查询失败的汇总，并提供“进入报名信息”。
- 查询失败或部分失败不能阻断后续填写。

## 8. 时间轴报名信息总览

### 8.1 核心结构

时间轴是报名信息簇的总览和导航，不直接编辑表单，也不是审核进度展示。

固定节点：

1. 学生信息
2. 家庭及户籍信息
3. 房产及居住信息
4. 材料上传

### 8.2 视觉形态

- 采用纵向时间轴，节点圆点和连线位于左侧，信息摘要位于右侧。
- 四个节点始终完整显示。
- 采用与信息预览一致的移动端单列分组样式，并保留左侧编号连线表达填写顺序。
- 以分割线和自然留白组织内容，不使用占据大面积空间的桌面仪表盘式卡片。
- 每个节点必须展示对家长有用的关键数据摘要，不能只保留标题和状态造成大片空白。
- 已完成节点使用成功色勾选，并显示 1–3 行关键摘要和数据来源。
- 待补充节点使用提醒色并显示问题数量或缺失内容。
- 未填写节点使用中性描边圆点。
- 社保、营业执照和父辈无房证明等条件性内容并入“材料上传”的摘要和编辑页。
- 时间轴底部独立展示“预览并提交”按钮，它不是时间轴节点。

### 8.3 节点行为

- 节点支持展开或折叠已填写数据，但不展开输入控件。
- 折叠箭头只负责展开或收起数据；独立的“修改”操作进入对应编辑页面。
- 折叠状态仍保留一行关键摘要、完成状态或待补充提示。
- 编辑页保存后返回时间轴，并刷新完成情况、摘要和来源标记。
- 退回修改时高亮问题节点，进入独立编辑页后定位具体字段或材料。
- 页面底部主操作为“预览并提交”，跳转到独立预览页面。

### 8.4 独立编辑页面

- 学生信息、家庭及户籍信息、房产及居住信息、材料上传分别使用独立页面。
- 页面顶部显示所属信息簇名称和自动保存状态。
- 部门共享数据自动预填，并标注“部门数据”。
- 家长修改后的字段标注“用户已修改”，关键字段就地填写修改原因。
- 页面底部使用“保存并返回”，不在编辑页直接提交整份报名。

### 8.5 字段状态

字段来源通过小型标签表达：

- 部门数据
- 家长填写
- 用户已修改
- 查询失败后补充

要求：

- 标签紧邻字段标题或值，不重复展示长说明。
- 自动填充字段仍允许编辑。
- 修改关键字段时，就地展开修改原因，不跳转到独立页面。
- 原始部门值不在家长普通填写界面反复展示；仅在修改确认和最终预览时以对比形式出现。

### 8.6 条件性信息

- 社保、营业执照、父辈无房证明按学校政策及前置填写动态出现。
- 首次出现时使用简短说明解释“为什么需要填写”。
- 系统不显示“你符合某类条件”或“建议选择某学校”。

## 9. 表单组件规范

### 9.1 标签与必填

- 标签置于控件上方，避免长中文标签挤压输入区域。
- 必填使用红色星号，同时在错误信息中说明缺失内容。
- 可选字段明确标注“选填”。
- 帮助说明放在标签下方或控件下方，不使用只靠问号图标承载的重要信息。

### 9.2 输入与选择

- 单行输入高度不低于 48 px。
- 证件号、手机号等使用适合的移动键盘类型。
- 地址使用多行输入或分层选择＋详细地址。
- 单选数量不超过 3 项时使用可见选项卡；更多选项使用弹出选择器。
- 不使用密集横排表格。

### 9.3 校验

- 失焦时进行格式校验，提交节点时进行完整性校验。
- 错误信息出现在对应字段下方，并在节点标题显示问题数量。
- 点击全局错误摘要可定位到具体字段。
- 部门查询失败与表单校验失败必须使用不同文案和视觉语义。

### 9.4 图片上传

- 上传区使用真实图片缩略图和“拍照／从相册选择”入口。
- 显示当前数量和最多 10 张限制。
- 上传中展示单张进度；失败只重试失败图片。
- 支持预览、替换、删除和拖动排序。
- 图片压缩不改变家长看到的操作流程。

## 10. 信息预览与提交

- 使用独立的自然高度长页面，不嵌入时间轴。
- 页面不受 844 px 首屏高度限制，按真实内容完整向下延伸。
- 不为展示全部数据而缩小字号、行高、间距或缩略图。
- 始终采用移动端单列布局；设计图按正常手机首屏比例展示，未显示的内容通过自然向下滚动查看。
- 禁止使用横向多列表格、缩小整页或桌面信息面板来模拟完整长页面。
- 按时间轴节点分组展示完整资料。
- 每个分组提供“修改”入口并返回对应节点。
- “用户已修改”和“查询失败后补充”字段使用醒目标识。
- 关键字段被修改时，以“部门返回值／本次申报值”上下对比展示，避免挤在同一横行。
- 长文本自然换行，每行只承载一组字段名和字段值。
- 材料按名称和图片缩略图分组展示。
- 页面底部展示真实性声明勾选项。
- 主按钮文案使用“确认提交报名”。
- 提交时展示明确的处理中状态，防止重复点击。
- 提交成功页展示报名编号、学生、学校和“查看报名详情”。
- 成功页不使用夸张庆祝效果，避免被误解为审核或录取成功。

## 11. 我的报名与状态表达

### 11.1 列表

- 默认展示当前招生年度，支持筛选历史年度、学生和学段。
- 卡片展示学生、学校、学段、状态、报名编号和更新时间。
- 同一学生存在历史初审不通过记录和新报名时，按时间倒序清楚区分。

### 11.2 状态样式

| 状态 | 视觉语义 | 主要操作 |
|---|---|---|
| 待提交 | 中性蓝灰 | 继续填写 |
| 审核中 | 品牌蓝 | 查看详情 |
| 退回修改 | 提醒橙 | 去修改 |
| 初审通过 | 成功绿 | 查看安排 |
| 初审不通过 | 错误红 | 查看原因／重新报名 |
| 已录取 | 成功绿强化 | 查看录取结果 |

### 11.3 报名详情

- 顶部状态卡展示当前状态及一句解释。
- 退回修改展示问题清单、老师意见和重新提交入口。
- 初审通过但线下安排未发布时显示“线下审核安排待公布”。
- 安排发布后展示日期、时间、地点、携带材料和注意事项。
- 暂未确定录取学校时维持初审通过，并显示“录取结果待公布”。
- 已录取后突出最终录取学校和结果发布时间。
- 不使用完整报名流程时间轴；状态信息采用状态卡和分组详情。

## 12. 内容型页面模板

### 12.1 报名时间

- 使用学段切换和城区／非城区／民办分组卡片。
- 每项只显示开始时间、截止时间。
- 不显示当前状态。

### 12.2 政策与操作指南

- 使用搜索或分类列表＋图文详情模板。
- 正文标题、发布日期、适用范围和内容层级清晰。
- 支持返回顶部，不设置悬浮分享按钮。

### 12.3 常见问答

- 顶部关键词搜索。
- 分类筛选横向滚动。
- 问题采用折叠列表，一次只建议展开一个答案。

### 12.4 查学区

- 顶部地址搜索与明确的查询按钮。
- 结果卡展示学校、招生范围和政策入口。
- 参考提示固定出现在结果上方，不用弱灰小字隐藏。
- 不提供“一键报名该校”。

## 13. 公开查询页面

### 13.1 查询首页

- 初审查询和录取查询使用独立标题及说明。
- 表单字段为学生姓名、证件号码后六位和图形验证码。
- 查询按钮在信息完整后可用。
- 页面明确说明查询用途和隐私保护规则。

### 13.2 查询结果

- 仅展示脱敏学生姓名和证件号后四位。
- 初审结果页展示初审结果和线下审核安排。
- 最终结果页展示已发布录取学校；未确定时显示“录取结果待公布”。
- 查询失败统一使用“未查询到匹配结果或信息有误”。
- 不通过错误文案、颜色或加载时长暴露学生是否存在。

## 14. 反馈与异常状态

- 加载：优先使用骨架屏，避免全屏旋转加载遮挡上下文。
- 空状态：说明为什么为空，并提供一个明确后续动作。
- 保存成功：使用轻量文字反馈和更新时间，不频繁弹窗。
- 网络异常：保留当前输入，提供重试。
- 部门查询失败：说明可继续手填，不得使用“无法报名”等阻断性文案。
- 上传失败：定位到具体图片，允许单张重试。
- 提交冲突：提示报名已在其他页面更新，先刷新查看最新内容，避免覆盖。

## 15. 文案规范

- 使用“家长”“学生”“学校老师”，避免内部术语。
- 使用“部门数据”“家长填写”“用户已修改”，不暴露接口名称或错误码。
- 使用“初审通过”，不使用“资格校验通过”。
- 使用“录取结果待公布”，不使用“未录取”。
- 使用“保存并继续”“确认提交报名”“去修改”，避免仅写“确定”。
- 风险提示说明事实和解决办法，不使用指责或恐吓语气。

## 16. 动效

- 页面切换和卡片展开使用 160–220 ms 的轻量过渡。
- 时间轴节点展开保持当前位置稳定，避免整页跳动。
- 保存、查询和上传状态采用局部反馈。
- 尊重系统“减少动态效果”设置。
- 不使用持续漂浮、呼吸光圈或庆祝粒子。

## 17. 易用性与无障碍

- 触控目标建议不小于 44 × 44 px。
- 输入框、按钮和选择器具有明确可见标签。
- 所有图标配合文字或可访问名称，重要操作不能只使用图标。
- 错误信息与字段建立明确关联。
- 状态除颜色外同时使用文字和图标。
- 支持系统字体放大后的自然换行，主操作不能被遮挡。
- 软键盘弹出时当前输入和错误提示保持可见。
- 图片上传入口支持相册和拍照，并清楚说明数量和大小限制。

## 18. 组件使用约束

基于 Ant Design Mobile 复用以下能力：

- NavBar、Card、List、Form、Input、TextArea
- Selector、Picker、Popup、Checkbox、Radio
- SearchBar、Tabs、Collapse
- ImageUploader、ImageViewer
- Dialog、Toast、ErrorBlock、Skeleton

需要业务封装的组件：

- 招生入口卡片
- 学校选择卡片
- 我的报名摘要卡
- 报名状态卡
- 报名信息时间轴
- 数据来源标签
- 部门数据对比字段
- 条件性材料组
- 线下审核安排卡
- 公开查询结果卡

业务组件只属于招生模块；只有经过两个以上应用验证的通用能力才能下沉到平台共享层。

## 19. 首轮高保真 UI 图要求

首轮输出 10 张关键页面，统一使用 390 × 844 px 画布：

1. 首页
2. 学段与类别选择
3. 学校列表
4. 学校政策阅读
5. 数据预处理
6. 学生信息独立编辑页
7. 时间轴报名信息总览
8. 加高版信息预览与提交
9. 我的报名详情
10. 公开查询及结果

表现要求：

- 使用真实、合理的中文示例数据。
- 重点页面需要覆盖退回修改、初审通过或接口失败后的可继续填写状态。
- 不使用底部 TabBar、消息入口、学校名额、自动资格判断或“未录取”状态。
- UI 图用于视觉与交互确认，不代表已经开始前端开发。

## 20. 设计验收清单

1. 首页所有关键入口在首屏或一次自然滚动内可找到。
2. 家长在总览页能看到四个完整时间轴节点，并通过箭头进入各自的独立编辑页面。
3. 学校卡片没有当前状态和名额信息。
4. 部门数据、家长填写和用户修改能够被清晰区分。
5. 部门接口失败时有明确、可继续的手填路径。
6. 退回原因可定位到具体字段或材料。
7. 初审通过与最终录取在视觉和文案上不混淆。
8. 公开查询结果严格脱敏且不泄露家庭资料。
9. 页面不存在底部 TabBar和独立消息中心。
10. 主要文字、触控尺寸、错误提示和软键盘场景满足移动端易用要求。
